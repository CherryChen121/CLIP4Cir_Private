# CLIP4Cir 模型输出整理设计

## 背景

项目当前把训练产物直接写入 `models/`。该目录约 99 GB，历史实验目录混合了 CLIP 微调、Combiner 训练、指标和汇总文件；模型名中的 `/` 还会让 `ViT-B/32`、`ViT-L/14` 意外形成额外目录层级。`clip_fine_tune.py` 和 `combiner_train.py` 分别拼接自己的输出路径，命名规则也不完全一致。

本次工作需要先统一后续训练输出，再把历史实验迁移到新结构，识别并清理重复 checkpoint 与失败实验。只有迁移和校验全部完成后，才彻底移除实体 `models/` 路径。

## 目标

1. 后续训练默认输出到项目内 `outputs/`，不再创建 `models/`。
2. 目录按数据集、训练阶段、模型和运行标识分层，模型名不能注入额外路径层级。
3. 无损迁移有效历史实验，并为每个旧路径保存可审计的新旧路径映射。
4. 只把 SHA-256 完全一致的 checkpoint 视为重复模型。
5. 严格识别失败实验，避免删除仍在运行、最近更新或状态不明确的目录。
6. 在不额外占用约 99 GB 临时空间的前提下完成迁移和物理去重。
7. 验证全部通过后删除空的 `models/`，不保留兼容目录或符号链接。

## 非目标

- 不把参数相同但权重内容不同的随机种子实验视为重复。
- 不按指标高低删除已完成实验。
- 不自动删除无法分类的文件或疑似损坏但仍存在的 checkpoint。
- 不改变模型结构、训练算法、checkpoint 数据格式或预训练权重目录。
- 不整理 `pretrained_models/`。

## 新输出结构

```text
outputs/
├── migration_manifest.csv
├── migration_report.json
├── reports/
│   └── legacy/
└── <dataset-slug>/
    └── <training-stage>/
        └── <model-slug>/
            └── <YYYYMMDD-HHMMSS-microseconds-pPID>/
                ├── checkpoints/
                ├── training_hyperparameters.json
                ├── train_metrics.csv
                ├── validation_metrics.csv
                └── run_manifest.json
```

`training-stage` 只使用 `clip-finetune` 或 `combiner`。数据集和模型名统一转为小写 slug：连续的非字母数字字符替换为单个 `-`，并移除首尾 `-`。因此 `FashionIQ` 变为 `fashioniq`，`ViT-B/32` 变为 `vit-b-32`。

运行标识使用本地训练开始时间、微秒和 PID，既可排序，也能避免并发训练碰撞。历史目录缺少微秒时保留其原有时间精度；若规范化后的目标路径已存在，迁移必须报告冲突并停止，不能覆盖或自动改名。

每次新训练都写入 `training_hyperparameters.json`。模型权重写入 `checkpoints/`，替代旧的 `saved_models/`。指标文件继续位于运行目录根部。`run_manifest.json` 记录数据集、阶段、模型原名、规范化名称、开始时间、PID 和 checkpoint 相对路径。

## 输出路径组件

新增一个小型、无训练依赖的路径组件，负责：

- 规范化数据集、训练阶段和模型名称；
- 创建唯一运行标识；
- 解析 `--output-root`；
- 构造并创建运行目录及 `checkpoints/`；
- 生成 `run_manifest.json`。

`clip_fine_tune.py` 与 `combiner_train.py` 都新增 `--output-root` 参数，默认值为项目根目录下的 `outputs/`。相对路径按项目根目录解析，绝对路径原样使用。两个入口必须调用同一个路径组件，不能再自行拼接目录名。

`save_model()` 继续接收运行目录，但内部模型子目录改为 `checkpoints/`。README 中的训练输出说明和示例 checkpoint 路径同步改为新结构。`outputs/` 加入 `.gitignore`，历史产物和迁移报告不进入 Git。

## 历史迁移工具

新增独立迁移工具，默认执行 dry run；只有显式传入 `--apply` 才能修改文件。迁移按以下顺序执行：

1. 扫描 `models/`，以历史 `saved_models/`、训练指标、超参数文件和目录命名共同识别运行根目录，包括被 `ViT-B/32` 或 `ViT-L/14` 斜杠拆开的目录。
2. 对每个普通文件记录旧路径、预计新路径、类型、大小和 SHA-256。
3. 根据旧目录前缀与超参数推断数据集、训练阶段、模型原名和运行标识；推断不唯一时标记为未解决，不执行删除阶段。
4. 把可识别的有效实验移动到 `outputs/.staging/` 下对应的临时目标。
5. 在临时目标重新计算文件大小和 SHA-256，与移动前清单逐项比较。
6. 校验通过后，将临时目录原子重命名到正式目标。
7. 对 SHA-256 和大小都相同的 checkpoint 执行物理去重。
8. 把历史汇总 Excel 等已识别的非运行报告移动到
   `outputs/reports/legacy/<legacy-relative-path>`，保留源目录相对层级，
   使不同训练阶段的同名报告分别归档且绝不覆盖。
9. 记录并删除符合严格条件的失败实验。
10. 重新扫描源目录和目标目录，生成最终 CSV 清单与 JSON 汇总。
11. 仅当不存在活跃、跳过、冲突、未知或校验失败项，且 `models/` 已空时，使用 `rmdir` 删除空目录树和最终的 `models/`。

所有移动都发生在同一文件系统内，使用重命名而不是复制，因此不需要再准备约 99 GB 空间。若源目录与目标目录不在同一文件系统，`--apply` 必须拒绝执行。

## 重复模型处理

checkpoint 候选扩展名为 `.pt`、`.pth`、`.ckpt` 和 `.safetensors`。只有文件大小相同且 SHA-256 完全一致时才属于同一重复组。大小相同但哈希不同的文件必须保留。

每个重复组按规范化目标路径的字典序选择一个规范副本。其他实验的 checkpoint 路径仍然保留，但冗余文件内容由指向规范副本 inode 的硬链接替换。替换过程先在同目录创建临时硬链接，再用原子替换覆盖冗余 inode。这样每个实验仍可按自己的 checkpoint 路径加载权重，磁盘上只保存一份物理数据。

迁移清单记录重复组、规范副本、每个链接路径和最终 inode。迁移后的验证要求同组文件 SHA-256 相同、inode 相同且链接数符合预期。去重只处理已经停止写入的历史实验，不在训练过程中自动去重。

## 失败实验判定

一个历史运行只有同时满足以下全部条件才可删除：

1. 不存在大小大于零的 checkpoint 候选文件；
2. 不存在大小大于零的 `*metrics*.csv`；
3. 目录名中的 PID 不存活，并且没有相关训练进程正在写入旧输出根目录；
4. 目录内最新文件的修改时间距执行时至少 24 小时。

非空但无法完成格式检查的 checkpoint 不按失败实验删除，而是标记为未解决并阻止删除 `models/`。失败实验的旧路径、文件列表、大小、最新修改时间和判定原因必须先写入迁移清单，随后才能删除该精确目录。

没有非空 checkpoint、但存在非空指标 CSV 的历史运行不属于失败实验。
这类运行按 metrics-only 指标归档实验保留，迁移其超参数、指标、日志及目录内
其他普通文件，并在清单中记录 `metrics-only-retained` 原因。它们使用与普通
历史运行相同的目标层级和哈希验证，但不要求 `checkpoints/` 内存在模型文件。
不足 24 小时且没有 checkpoint 或指标的运行仍保持未解决状态，不能因为其他
metrics-only 运行已获准迁移而提前删除。

## 活跃训练与并发安全

代码修改先于历史迁移完成，使新启动的训练默认写入 `outputs/`。迁移 apply 阶段启动前重新检查 `clip_fine_tune.py`、`combiner_train.py` 相关进程以及旧运行 PID。只要存在可能写入 `models/` 的进程，迁移工具就拒绝修改源目录；dry run 仍可执行。

扫描完成后、每次移动前再次检查源目录的大小和最新修改时间。任何变化都会让该运行变为未解决项并停止删除阶段。迁移不覆盖现有目标，不跟随源目录内指向外部的符号链接，也不跨文件系统操作。

## 清单与可恢复性

`migration_manifest.csv` 每行记录一个运行或文件动作，至少包含：

- 旧路径和新路径；
- 数据集、阶段、模型 slug 和运行标识；
- 动作状态：`moved`、`deduplicated`、`deleted-failed`、`skipped-active`、`unresolved` 或 `error`；
- 文件大小、SHA-256、重复组和规范副本；
- 失败判定依据或错误信息。

`migration_report.json` 保存总运行数、总文件数、迁移字节数、去重前后物理字节数、失败实验数及各状态计数。有效实验在源目录删除前已经完成目标哈希校验；重复 checkpoint 的规范副本仍保留完整内容。任何错误都会保留 `models/`，以便根据清单恢复或重试。

## 删除门槛

实体 `models/` 只能在以下条件全部成立后删除：

- 两个训练入口默认输出到 `outputs/`，相关自动化测试通过；
- 项目代码和 README 不再引用旧输出根目录；
- 没有可能写入旧根目录的训练进程；
- 所有有效历史文件移动前后的大小和 SHA-256 一致；
- 所有重复组的硬链接与规范副本验证通过；
- 所有失败实验均满足四项严格判定并已记录；
- 不存在 `skipped-active`、`unresolved`、`error`、未知文件或目标冲突；
- `models/` 中不再包含普通文件、符号链接或非空目录。

删除使用逐层 `rmdir`，不使用递归强制删除。删除后再次确认 `models` 路径不存在，并运行一次迁移 dry run，预期报告源目录不存在且无需处理。

## 测试与验收

单元测试覆盖：

- slug 规范化，包括斜杠、空白、连续特殊字符和空结果；
- 运行标识格式与并发唯一性；
- 相对及绝对 `--output-root` 解析；
- 两个训练入口暴露相同的输出参数并使用统一路径组件；
- 历史目录解析，包括斜杠导致的嵌套目录；
- 严格失败判定的四个条件及 24 小时边界；
- metrics-only 运行完整保留并迁移，且不会被归类为失败；
- 不同源目录中的同名 legacy 报表保留相对层级且目标路径不冲突；
- 活跃 PID、最近修改、未知文件、跨文件系统和目标冲突拦截；
- 相同大小不同哈希不去重；
- 相同哈希文件原子替换为同 inode 硬链接；
- dry run 不修改任何文件。

临时目录集成测试构造有效运行、重复 checkpoint、失败运行、活跃运行、未知文件和路径冲突，验证迁移状态、清单内容、目标层级、哈希、inode 与删除门槛。

真实迁移验收包括：

1. 保存 dry-run 汇总作为迁移基线；
2. 运行完整项目测试；
3. 执行 apply 并保存最终清单；
4. 比较迁移前有效文件数、逻辑字节数和迁移后对应值；
5. 重新计算所有 checkpoint 哈希并验证重复组 inode；
6. 确认新训练路径 smoke test 只创建 `outputs/` 下的目录；
7. 确认 `models/` 已被彻底移除。
